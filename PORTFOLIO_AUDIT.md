## 4. Quality audit

### Build and tooling
- `next build`: **passes**, no errors. One warning: `Browserslist: browsers data (caniuse-lite) is 6 months old`.
- `tsc --noEmit`: passes.
- `npm run lint`: **fails** — `Invalid project directory provided, no such directory: …\lint`. `next lint` was removed in Next 16; the declared `next ^14.2.3` and `eslint-config-next 14.1.0` don't match the installed 16.2.3. Lint has effectively not run since the override was added.
- `package.json` versions don't describe what's built. Anyone cloning with `npm install` gets the npm lockfile, not the pnpm overrides — unclear which Next version they'd end up on.

### Performance (what's visible in code)
- **Project images are 0.6–3.4 MB PNGs** (e.g. `souqpass.png` is 2400×1800, 1.1 MB; `eyoha.png` 3.4 MB). They're rendered as CSS `background: url(...)` in `components/project-card.tsx`, which bypasses `next/image`: no resizing, no AVIF/WebP, no lazy loading. One page of 9 cards loads roughly 10–15 MB of images.
- About image is a 32-frame animated GIF (`code.gif`, 480×360) declared at 800×800.
- Fonts: `next/font` Inter, self-hosted. Fine.
- No third-party or render-blocking scripts.
- Every section is a client component (`"use client"`) with GSAP. GSAP `Flip` is registered in `lib/gsap-client.ts` but never used.
- **Projects are not in the server HTML.** `ProjectsSection` reads `useSearchParams()` inside Suspense, so the static build renders only the skeleton; the client then fetches `/api/projects`. Verified: `curl http://localhost:3005/ | grep -c "Michu Mizan"` returns `0`. The data is a static JSON import, so the API round-trip adds a loading state for no benefit.
- Hero text animates in with `gsap.from({opacity:0})`, so the LCP element (the H1) is invisible until JS runs.
- Achievement numbers render as `0` in HTML and only count up on scroll; a crawler or no-JS reader sees "Years building: 0". Verified in the browser before scrolling.

### Accessibility
- **Heading order is broken.** Actual DOM order: `H1 Hello, I'm…` → `H2 About Me` → four `H2`s that are just numbers ("Projects shipped: 0+") → `H5 Let's connect` → `H3 Phone` → `H3 Email` → `H2 My Projects` → `H5` per project title.
- The H1 text is replaced every ~2 s by GSAP (`<Muhidin />` / `Web Developer` / `UI/UX Designer`). The page's main heading never states your name in plain text.
- **Mobile menu button has no accessible name** (icon only, no `aria-label`). `.hintrc` turns off the `button-name` rule, which hides this.
- **Hidden mobile menu links stay focusable**: the closed `<ul aria-hidden="true">` still contains 3 tabbable `<a>`s (verified).
- **Project repo/preview links are invisible until hover.** The overlay is `opacity-0` with `group-hover` only (no `group-focus-within`), so keyboard users tab onto invisible links, and touch users have no hover. Project titles aren't links.
- **Project screenshots have no alt text** (they are CSS backgrounds). The About GIF has alt "Code animation" but is decorative and should be `alt=""`.
- **Focus rings are near-invisible.** shadcn inputs and buttons use `ring-ring`, and `--ring` in `:root` is `222.2 84% 4.9%` (near-black). The `.dark` class is never applied, so the ring is near-black on `#121212`. Search/sort use `focus:outline-none` with a 1 px `stone-600` ring.
- **Contrast fails WCAG AA for most body text.** Measured against `#121212`: `stone-500` = 3.90:1 (hero paragraph, nav links, project descriptions, contact copy, stat labels, inactive filters); `stone-600` = 2.46:1 (placeholders, "All rights reserved"). `stone-400` = 7.43:1 passes.
- Nav links call `preventDefault()` + `scrollIntoView`, so focus doesn't move to the target section and the URL hash doesn't update.
- About tabs are plain buttons with no `role="tab"` / `aria-selected`.
- `<main>` wraps the navbar and footer. There's no skip link.
- **prefers-reduced-motion is handled well**: `lib/reduced-motion.ts` gates every GSAP effect, and the marquee and cursor spotlight are removed. Gaps: `TabButton` underline animation and the nav smooth scroll ignore it.

### SEO
- Title `Muhidin Misbah` has no role. The description `Personal portfolio website` is generic.
- No Open Graph or Twitter tags, no `metadataBase`, no canonical.
- No `sitemap.xml` or `robots.txt` (both 404 on the live site).
- No JSON-LD `Person` schema.
- Projects aren't in the HTML (see Performance), so crawlers see no project names.

### Responsive
- No horizontal scroll at 375 px (verified: `scrollWidth === innerWidth`).
- Fixed sizes: hero avatar 250 px / 400 px, project cards `min-h-[28rem]` / `30rem` (lots of empty space under short descriptions).
- The rotating H1 role changes width (`<Muhidin />` vs `UI/UX Designer`) at `xl:text-8xl`. Whether that wraps and shifts layout is unclear from code; it wasn't measured.

### Visual design (Refactoring UI)
- **No accent color.** The palette is only gray (`stone-*` + `zinc-*`) on `#121212`. `primary: colors.sky` is defined in `tailwind.config.ts` but never used. Nothing signals the primary action.
- **CTA hierarchy is flat.** "Hire Me" (`bg-zinc-800/90`) and "Download CV" (`bg-zinc-900`) look nearly the same.
- **Two gray families mixed.** Warm `stone` borders and text sit on cool `zinc` surfaces in the same element (e.g. `border-stone-700 bg-zinc-900/40`). The Projects heading uses `text-white` while every other heading uses `stone-100`.
- **De-emphasis goes too far.** The text recruiters need (hero summary, project descriptions) is the lowest-contrast text on the page (`stone-500`).
- **Type scale has no system.** H1 goes up to `text-8xl` (96 px); About and Projects headings are `text-3xl/4xl`; the Contact heading is `text-lg` (18 px), the same size as a project card title. About is left-aligned, Projects is centered.
- **Section spacing is ad hoc.** About uses `py-8 sm:py-12 md:py-16`, Achievements `py-8 sm:py-12`, Contact `my-12 py-20 md:py-24`, page `mt-24`. Contact ends up with a much larger gap than the other sections.
- **Too many borders, no depth.** Nav, stat strip, every card, contact cards, inputs, filter pills and pagination all use 1 px `stone-800` borders. `shadow-sm` on a near-black background doesn't show. Refactoring UI would replace most of these borders with spacing or background contrast.
- **No visual weighting of projects.** Bank platforms that moved ETB 210M+ get the same card as "Labubu or Lafufu".

### Template or distinctive build?
The base is a template. Component and prop names match the widely used `judygab/nextjs-portfolio-template` Next.js tutorial: `HeroSection` with "Hello, I'm" + "Hire Me" / "Download CV", `AboutSection` with a `TabButton` for Skills/Education/Certifications, `AchievementsSection` with `prefix`/`postfix` metrics, `ProjectTag` filters, `MenuOverlay`/`NavLink`, `EmailSection` titled "Let's connect" with GitHub/LinkedIn icons, and `bg-[#121212]`.

The custom work on top: the April 2026 GSAP layer (magnetic buttons, scroll-scrubbed marquees, cursor spotlight, 3D card tilt) and the JSON data layer with an API route, URL-synced filters and pagination. A recruiter who has seen that template will recognise the layout.

## 5. Code worth showing

Nothing here reads as non-obvious to a senior engineer. Two pieces are solid and clean:

1. **`lib/reduced-motion.ts`.** Reads `prefers-reduced-motion` through `useSyncExternalStore` with a server snapshot, so it's hydration-safe and reacts live when the OS setting changes. Every animated component checks it, and decorative layers unmount entirely. It's correct and used consistently, but not unusual.
2. **URL-synced project browsing** — `components/project-section.tsx` + `lib/projects.ts`. Debounced search writes to the query string with `router.replace(..., { scroll: false })`, an `AbortController` cancels stale fetches, and `queryProjects` clamps `page` and `pageSize`. A reviewer would also ask why a static JSON file goes through an API at all.

Stronger showcase material per the CV (Charge Hub's confirmation-gated UI with idempotent commands; self-hosted runners for CoopScale) is not in this repo.

## 7. Contact form: status and changes made

### Was it working?
**Partly, and it couldn't tell you when it failed.**

- `resend.emails.send()` in Resend v3 returns `{ data, error }`. It doesn't throw. `lib/mail.ts` ignored `error`, and `actions/email.ts` always returned `"Email sent!"`. Verified: a send that Resend rejects (422 `validation_error`) resolves normally, so the old form would have shown success.
- The form called `form.reset()` even on failure, wiping the visitor's message.
- Network or server errors weren't caught, so the UI stayed silent.
- The message was put into HTML unescaped (`<p>${message}</p>`), allowing HTML injection into your inbox.
- No `reply_to`, so replying went to `onboarding@resend.dev`.
- No spam protection. `message` accepted an empty string.
- Sender is `onboarding@resend.dev`, which only delivers to the email address that owns the Resend account. The Resend account has **no verified domains** (`GET /domains` → empty). So the form only reaches you if your Resend login is `misbahmuhidin@gmail.com`. Unclear from code. **Not verified with a real send** — that needs your go-ahead.
